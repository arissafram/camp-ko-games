Core Concepts

Forget how something works? Look it up here. These are the tools we’ll use to make our games work.

HTML + CSS + JavaScript

Three tools build a webpage together: HTML puts things on the page, CSS makes them look good, and JavaScript makes them do things.

HTML

<button>Click me</button>

CSS

button {
  font-size: 24px;
}

JavaScript

console.log("Hello!");

You might use this for: every game on this site — all three working together.

The DOM

The DOM is how JavaScript finds and changes things on your page.

let scoreDisplay = document.getElementById("score");
scoreDisplay.textContent = "Score: 10";

You might use it for: updating a score, changing text, or showing a win message.

console.log()

console.log() lets you peek at what your code is doing while it runs.

let score = 10;
console.log(score);

You might use it for: checking a variable’s value, confirming a function ran, or debugging when something’s not working.

Variables

A variable lets JavaScript remember something.

const playerName = "Alex";
let score = 0;

Most of the time, we’ll use let when a value needs to change and const when it doesn’t. You may also see var in other JavaScript code.

You might use one for scores, player names, lives, speed, or whether the game is over.

Strings, Numbers + Booleans

These are the different types of things a variable can remember.

let playerName = "Pickle";  // string
let score = 10;             // number
let gameOver = false;       // boolean
  • String = text
  • Number = a number
  • Boolean = true or false

You might use these for: text (string), scores or lives (number), and yes/no situations like game over (boolean).

Arrays

An array stores a list of things.

let animals = ["dog", "cat", "raccoon", "frog"];

You might use one for characters, cards, questions, choices, or possible answers.

Objects

An object keeps related information together.

let player = {
  name: "Pickle",
  lives: 3,
  score: 10
};

You might use one to bundle up everything about a character, card, or item in one place.

Functions

A function is a set of instructions you can reuse whenever you need it.

function celebrate() {
  console.log("You did it!");
}

celebrate();

You might use one for what happens when you score, click something, start a round, or win.

Events + Event Listeners

An event is something that happens — a click, a key press, a submitted answer. An event listener waits for it and tells JavaScript what to do next.

button.addEventListener("click", celebrate);
WHEN this happens → DO this

You might use one for: clicks, key presses, or anything else the player does.

User Input

Your game can use information that a player types or picks.

let playerName = nameInput.value;

You might use it for: player names, answers, or guesses — anything the player provides.

Conditionals

Conditionals let your code decide what to do based on whether something is true or false.

if (score >= 10) {
  console.log("You win!");
} else {
  console.log("Keep going!");
}

You might use it for: winning, losing, checking answers, matching cards, reaching a finish line, or deciding what happens next.

Comparison Operators

Comparison operators compare two things. JavaScript answers the comparison with true or false.

  • === equal to
  • !== not equal to
  • > greater than
  • < less than
  • >= greater than or equal to
  • <= less than or equal to
score >= 10
answer === "yes"

Comparisons help your game check things like scores, answers, lives, and time.

Logical Operators

Logical operators let you check more than one thing at a time.

  • && AND — both things must be true
  • || OR — at least one thing must be true
  • ! NOT — flips true and false
if (score >= 10 && timeLeft > 0) {
  console.log("You win!");
}

The score has to be at least 10 AND there still has to be time left.

if (lives === 0 || timeLeft === 0) {
  console.log("Game over!");
}

The game ends if you’re out of lives OR out of time.

if (!gameOver) {
  // keep playing
}

! means NOT. Here, the game keeps going if the game is not over.

forEach

You already know how to make a list — an array (see Remembering Things). forEach does something once for every item in it.

let animals = ["dog", "cat", "frog"];

animals.forEach(function(animal) {
  console.log(animal);
});

You might use it for: showing every card, checking every answer, or moving every enemy on screen.

Random Choices

Math.random() lets JavaScript pick something at random.

const choices = ["cat", "dog", "frog"];

const randomIndex = Math.floor(Math.random() * choices.length);
const choice = choices[randomIndex];

This picks a random item out of the list — you don’t need to know the math to use it.

You might use it for: random enemies, random questions, random rewards, or shuffling cards.

Timers

JavaScript can wait, then make something happen.

setTimeout(function() {
  console.log("Time's up!");
}, 2000);

2000 means 2 seconds. You might use a timer for rounds, countdowns, or messages that disappear.

Keyboard Input + Movement

Games can respond when a player presses a key.

document.addEventListener("keydown", function(event) {
  console.log(event.key);
});

You might use it for: moving a character, controlling a paddle, or triggering an action.

Pseudocode

Pseudocode means planning what your code should do, in plain language, before writing any JavaScript. Ask yourself:

  • What appears on screen?
  • What does the game need to remember?
  • What makes something happen?
  • What happens next?
START with a score of 0

WHEN the player clicks:
    add 1 to the score
    show the new score

You might use this for: planning any part of your game before you code it.

Breaking Down a Problem

Big problems are easier when you turn them into little ones. Instead of “Build a game,” ask the pseudocode questions above, then solve one piece at a time.

Debugging

A bug is something in your code that isn’t working the way you expected. Debugging means figuring out why — and it’s a normal part of programming.

  1. What did I expect?
  2. What actually happened?
  3. Where can I check what’s going on?
  4. Change one thing.
  5. Try again.

Testing

Don’t wait until your game is finished to test it. Play it. Break it. Give it to someone else.

  • Does it work?
  • Is anything confusing?
  • What happens if I do something unexpected?

Reading Errors + Using the Console

When something breaks, the console often tells you exactly where and why.

You might use it for: finding typos, catching mistakes, and figuring out where to start debugging.

Asking for Help

Good questions get better help — including from AI. When you ask, explain:

  • What you’re trying to make happen
  • What you expected
  • What actually happened
  • What you’ve already tried

Use AI to understand, debug, and ask questions — not to build the whole thing for you.
